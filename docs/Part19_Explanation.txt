=====================================================================
PART 19 - BONUS: TWO SWITCHES JOINED BY A TWO-PIPE TRUNK
=====================================================================

1. WHAT THE ROADMAP ASKS
------------------------
./switch <tcpA> <num_ports> --pair <tcpB> [-c a.conf] [--peer-config b.conf]: two pipes, fork; the child is switch B (own TCP port, shm, socket, log named by its TCP port),
the parent is A. Each side attaches its pipe ends to port 0 as a trunk with rfd != wfd. A uses pipe1 to write and pipe2 to read, B the opposite; each closes the two unused
ends right after the fork. Port 0 uses the same receiver, sender, queue, VLAN and trunk logic, is not counted in num_ports or the semaphore, is exempt from port security, is not
reachable by accept. Learning across the link is automatic. A dead peer: EOF / EPIPE, port 0 DISABLED and logged, the local switch keeps working. SIGINT reaches both; A calls
waitpid for B. The child resets the signal mask and set-up exactly like main; fork before creating any thread.

3. DESIGN DECISIONS
-------------------
* Pipes cannot be shutdown(): a receiver blocked in read() on a pipe would never wake for a local teardown. Both threads of port 0 therefore wait in poll() on {pipe, eventfd}; the
  reaper writes the eventfd. A frame is one write() of at most 1517 bytes (< PIPE_BUF), which is atomic: once poll() says readable, the whole frame is there, so the following
  read_full() cannot block on a half-sent frame. A sender polls POLLOUT first, so a stalled peer (full pipe) cannot keep it in write() when the teardown comes.
* A peer that does not exit when A shuts down (SIGSTOPped, hung) must not hang A: poll() on a pidfd, 15 s, then SIGKILL. No sleeping, no spinning.
* PR_SET_PDEATHSIG: a B whose A was killed with SIGKILL gets SIGTERM and shuts down cleanly (the signal is blocked and taken by B's signal thread).
* Port 0 ends DISABLED, never FREE: nobody can connect to it, and there is no token to give back.
* No lock is new; fork() happens before any lock or thread exists.

4. TESTS (tests/test_pair.py, 76 checks per variant)
----------------------------------------------------
forwarding across the link in VLAN 10 and VLAN 20, no echo, vlan field kept, 1500-byte payload, show mac / show ports / stats rows for port 0, both shm segments and sockets,
swctl -p <B>; port 0 exempt from port security (12 MACs behind it with a limit of 3); SIGINT to the process group, to A only, SIGTERM to B only; kill -9 B (A keeps switching, reports
the signal); kill -9 A (B follows); SIGSTOP B while A floods (A exits, B killed after the grace period); a flood across the link then SIGINT; 6 bad command lines.
